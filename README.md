# Параллельный запуск утилиты по файлам эксперимента

Утилита обрабатывает один эксперимент примерно за десять минут. Экспериментов много,
и последовательный прогон занял бы сутки. Эта программа держит несколько запусков
одновременно и доводит очередь до конца, переживая обрывы.

Зависимостей нет — нужен только Python 3.9 или новее. Перенос на другую машину это
копирование папки, ставить ничего не надо.

```
python3 runner.py --dir /Users/munir/exp --mode create
```

## Как разложены файлы

`--dir` это корень, внутри которого лежат папки по видам файлов. Идентификатор
эксперимента связывает их между собой — это номер и, если он есть в именах,
название кластера:

```
/Users/munir/exp/
  configs/
    config_103m4.yml
    config_103m5.yml
    config_104m5.yml
  affects/
    affect_enable_103m4.yml
    affect_disable_103m4.yml
    affect_enable_103m5.yml
    affect_disable_103m5.yml
    affect_enable_104m5.yml
    affect_disable_104m5.yml
```

**103m4 и 103m5 — два разных эксперимента.** Один и тот же номер на разных кластерах
нигде не смешивается: ни в очереди, ни в журнале, ни в папках с логами. Кластер
необязателен — `config_103.yml` без него тоже подойдёт и будет жить рядом.

Раскладка задаётся в `config.json` и меняется без правки кода — папка указывается
прямо в паттерне, поэтому отдельного аргумента на каждую папку не нужно.

Такая структура уже разложена в `example/` и запускается одной командой на заглушке
вместо настоящей утилиты — посмотреть работу целиком можно за пару секунд:

```bash
python3 runner.py --dir example --config example/config.json --mode all
```

## Порядок первого запуска

Ошибка в шаблоне команды стоит десять минут, поэтому вводить в работу стоит по шагам:

```bash
python3 runner.py --dir /Users/munir/exp --mode all --dry-run      # 1. сверить команды глазами
python3 runner.py --dir /Users/munir/exp --mode all --only 103m5   # 2. один настоящий эксперимент
python3 runner.py --dir /Users/munir/exp --mode all                # 3. полный прогон
```

На многочасовой прогон запускайте под `caffeinate`, иначе Mac уснёт в середине:

```bash
caffeinate -i python3 runner.py --dir /Users/munir/exp --mode all
```

Даже если уснёт — журнал на диске, повторный запуск продолжит с места обрыва.

## Аргументы

| Аргумент | Что делает |
|---|---|
| `--dir PATH` | корневая папка с `configs/` и `affects/` (обязательный) |
| `--mode` | какие шаги выполнять: `create`, `create,enable` или `all` — все шаги из конфига по порядку. По умолчанию `create` |
| `--workers N` | сколько запусков утилиты держать одновременно |
| `--out DIR` | куда складывать журнал и логи, по умолчанию `./storm_runs` |
| `--only 103,105m4,107-112` | только эти эксперименты. Голое число берёт все кластеры этого номера, `105m4` — ровно один |
| `--limit N` | только первые N экспериментов |
| `-r`, `--recursive` | искать файлы и во вложенных папках |
| `--dry-run` | показать готовые команды и выйти, ничего не запуская |
| `--timeout SEC` | переопределить таймаут шага |
| `--attempts N` | сколько попыток на шаг |
| `--force` | игнорировать журнал, прогнать всё заново |
| `--only-failed` | взять только то, что раньше не прошло |
| `--config PATH` | другой config.json |
| `--state PATH` | другой файл журнала |

Коды возврата: `0` — всё прошло, `1` — были провалы, `2` — ошибка в конфиге или аргументах.

## config.json

В JSON нельзя писать комментарии, поэтому поля описаны здесь.

### Верхний уровень

| Поле | Значение |
|---|---|
| `exe` | имя утилиты в PATH или полный путь к бинарю |
| `workers` | сколько запусков одновременно |
| `attempts` | попыток на шаг: `3` это одна основная и два ретрая |
| `retry_delay_sec` | пауза перед повторной попыткой |
| `success_exit_codes` | какие коды возврата считать успехом |

### `patterns` — какие бывают файлы и где они лежат

```json
"patterns": {
  "config":  "configs/config_{n}.yml",
  "enable":  "affects/affect_enable_{n}.yml",
  "disable": "affects/affect_disable_{n}.yml"
}
```

`{n}` — это номер эксперимента вместе с названием кластера, если оно есть: под него
подходят и `config_103.yml`, и `config_103m5.yml`. Остальное в паттерне совпадает
буквально. Файлы связываются в эксперимент по этому идентификатору:
`config_103m5.yml` идёт вместе с `affect_enable_103m5.yml`.

Идентификатор должен начинаться с цифры и состоять из букв и цифр. Подчёркивание
в него не входит — поэтому случайный `config_103m5_старый.yml` не станет
самостоятельным экспериментом, а будет просто проигнорирован.

Слева от имени файла — папка относительно `--dir`. Можно указать и абсолютный путь,
если какой-то вид файлов лежит совсем в другом месте.

Ключи здесь произвольные: имя ключа становится плейсхолдером. Появится ещё один вид
yml — допишите строчку в `patterns`, и `{новая_роль}` можно использовать в командах.
Заняты только служебные имена `{n}`, `{dir}`, `{taskdir}`, `{outdir}`.

Требуются только те файлы, которые реально используются выбранными шагами. Шагу `stop`
с аргументами `["-c", "{config}"]` affect-файлы не нужны, и их отсутствие не помешает.

### `steps` — сами команды

```json
"steps": {
  "create":  { "args": ["-c", "{config}", "-f", "{enable}", "-e"], "timeout_sec": 2400 },
  "enable":  { "args": ["-c", "{config}", "-u", "-f", "{enable}", "-e"], "timeout_sec": 300 },
  "disable": { "args": ["-c", "{config}", "-u", "-f", "{disable}", "-e"], "timeout_sec": 300 },
  "stop":    { "args": ["-c", "{config}"], "timeout_sec": 2400 }
}
```

Шаги можно называть как угодно и добавлять новые — имя из `steps` и есть значение `--mode`.

`args` это **список**, а не строка: каждый элемент уезжает в argv отдельно, поэтому
пробелы и спецсимволы в путях не требуют кавычек и ничего не ломают.

`timeout_sec` — сколько ждать до принудительного убийства. `2400` это четырёхкратный
запас к ожидаемым десяти минутам. `0` отключает таймаут.

При `--mode create,enable` шаги идут цепочкой: если `create` провалился, `enable`
для этого эксперимента не запускается.

Опечатка в плейсхолдере — ошибка, а не молчаливая подстановка: `{enabel}` остановит
запуск на первой секунде вместо того, чтобы уехать в утилиту литеральной строкой.

### Плейсхолдеры

Для эксперимента 103m5 в папке `/Users/munir/exp`:

| Плейсхолдер | Значение |
|---|---|
| `{config}` | `/Users/munir/exp/configs/config_103m5.yml` |
| `{enable}` | `/Users/munir/exp/affects/affect_enable_103m5.yml` |
| `{disable}` | `/Users/munir/exp/affects/affect_disable_103m5.yml` |
| `{n}` | `103m5` |
| `{dir}` | `/Users/munir/exp` |
| `{taskdir}` | рабочая папка этого шага |
| `{outdir}` | значение `--out` |
| `{root}` | папка, где лежит `runner.py` |

Пути всегда абсолютные. Незнакомые фигурные скобки в аргументах остаются нетронутыми —
если у утилиты есть свой синтаксис со скобками, он не сломается.

### `run` — как запускать и как оценивать результат

| Поле | Значение |
|---|---|
| `isolate_cwd` | запускать каждый шаг в своей папке `storm_runs/runs/{n}/{step}/attempt{k}/` |
| `collect` | какие файлы забрать из рабочей папки после выполнения |
| `fail_regex` | если найдено в логах — считать провалом даже при нулевом коде возврата |
| `success_regex` | если задано и не найдено в логах — считать провалом |

`isolate_cwd` включён не для порядка. Утилита пишет логи сама, и если она делает это
по фиксированному имени, то шестнадцать параллельных запусков в общей папке затрут
результаты друг друга. Выключайте только если утилита требует запуска из конкретной
папки — тогда она унаследует ту, из которой запущен `runner.py`, а всё, что она напишет,
будет скопировано в папку попытки по глобам из `collect`. В этом случае сузьте `collect`
до конкретных имён: `**/*.log` заставит после каждого шага обходить всё дерево рабочей
папки, а параллельные запуски всё равно будут писать в одно и то же место.

`fail_regex` пригодится, если утилита рапортует об ошибке текстом, но возвращает `0`.

## Что получается на выходе

```
storm_runs/
  state.jsonl                      журнал, он же основа возобновления
  report.txt                       итоговый отчёт
  runs/103m5/create/attempt1/      рабочая папка шага
      stdout.log                   вывод утилиты
      ...                          всё, что утилита написала сама
```

## Возобновление после обрыва

Каждая попытка попадает в `state.jsonl` строкой JSON, файл сбрасывается на диск сразу.
Ключ записи — пара «номер эксперимента + шаг», поэтому повторный запуск не станет
пересоздавать то, что уже создалось, даже если следующий шаг не успел пройти.

```bash
python3 runner.py --dir ... --mode all               # продолжит с места обрыва
python3 runner.py --dir ... --mode all --only-failed # только то, что падало
python3 runner.py --dir ... --mode all --force       # заново, журнал игнорируется
```

Номер попытки сквозной: перезапуск упавшего шага пишет в `attempt2`, а логи первой
неудачи остаются на месте — по ним и разбираются, почему не получилось.

`Ctrl+C` останавливает набор новых экспериментов и даёт доработать текущим.
Второй `Ctrl+C` убивает активные процессы вместе с их потомками.

## Если что-то не запускается

**«утилита не найдена ни в PATH, ни как файл»** — скорее всего это алиас или функция
из `.zshrc`. Программа запускает утилиту без шелла (так пути с пробелами не ломаются),
а алиасы существуют только внутри шелла. Посмотрите `type storm` и впишите в `exe`
полный путь к настоящему бинарю.

**«папка для роли не найдена»** — в паттерне указана подпапка, которой нет.
Сверьте `patterns` с тем, как у вас разложены файлы.

**«по паттерну не найдено ни одного файла»** — имена не совпадают. Программа покажет
несколько файлов из этой папки для сравнения. Регистр учитывается.

**Номера пропускаются с сообщением про недостающие роли** — у эксперимента нет всех
файлов, которые нужны выбранным шагам. Это предупреждение, а не ошибка: остальные
эксперименты отработают, а список пропущенных попадёт в `report.txt`.

## Тесты

```bash
python3 -m unittest discover -s tests -t .
```

Тесты используют заглушку `tests/fake_storm.py` вместо настоящей утилиты и проверяют
в том числе, что параллельный прогон действительно быстрее последовательного, что
`enable` и `disable` не путаются между собой и что логи параллельных запусков не
перетирают друг друга. Прогоните их на Mac перед боевым запуском: ветка управления
процессами для macOS на Windows не исполняется ни разу.
